🕸️ Graph Layers
These are conceptual layers in the heterogeneous legal graph. They are not rendered as hard horizontal bands, but they explain why some nodes sit close to the case root while others act like bridges across multiple cases.
Layer 1

Case Anchor

The orange case node is the supervision target. At training time, the classifier reads the final embedding of this node to predict outcome.

⚖️ case
Layer 2

Section Text

These nodes keep the leakage-safe textual structure close to the case root. They represent preamble, facts, arguments, and side-specific argument slices.

📄 preamble 📋 facts 💬 arguments 🗣 petitioner_arguments 🛡 respondent_arguments
Layer 3

Parties and Forum

These nodes describe who is involved and where the matter is heard: petitioner, respondent, judge, and court. Some of them are local, some are reused globally.

👤 petitioner 🏛 respondent 👨‍⚖️ judge 🏛 court
Layer 4

Counsel and Authorities

Lawyers and cited authorities are the strongest bridges across cases. They let the graph carry signals from one matter to another through shared legal context.

👔 petitioner_lawyer 🥋 defence_lawyer 📜 statute § provision 📗 precedent
Layer 5

Global Shared Layer

When two cases hit the same shared node, they become graph neighbors in the global structure. In the graph tab, the dashed case nodes are a visual summary of those cross-case overlaps.

🧠 Model Stack
The implementation in src/models/hetero_gnn.py follows a simple pipeline: type-specific input projections, a configurable stack of heterogeneous graph convolutions, then an MLP head over the final case embedding.
1

Input Projection

Each node type gets its own linear projection into a shared hidden size, then receives a learned type embedding. That puts text, judges, statutes, and other node families into the same latent space.

Linear(node_type) type embedding
2

Heterogeneous Message Passing

With architecture: hgt, each layer uses HGTConv. The model keeps separate attention projections per node/edge type pattern, so a judge-to-case signal is not treated like a statute-to-arguments signal.

HGTConv × N num_heads
3

Residual Refinement

After every convolution, the model applies dropout, adds the residual, normalizes with LayerNorm, and then applies ReLU. That stabilizes training while still letting each node type evolve across layers.

dropout residual LayerNorm
4

Case Readout

The final hidden vector for the case node goes into a 2-layer MLPHead. That is the point where the graph has already mixed text, forum, counsel, and authority signals into one representation.

hidden["case"] MLPHead logits

How To Read The Graph Tab

  • The large orange case node is the current focus case.
  • Its nearby section and entity nodes are the local case-star context.
  • Smaller dashed case nodes are other sample cases that overlap on shared graph nodes.
  • The dashed links are a visual shortcut so those related cases are visible without expanding their full local stars.

What Matters For Outcome Prediction

The model does not make predictions from a single text blob. It learns from the combination of section text, who appeared in the matter, what court heard it, and which legal authorities were cited. Cross-case sharing is useful because it lets similar structural patterns reinforce one another during message passing.
